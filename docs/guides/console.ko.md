# 콘솔(`run-console`)

> 🇬🇧 English version: [console.md](./console.md)

CLI와 같은 진입점 위에 올린 로컬 웹 앱입니다. 질문하고 답변의 각 출처를
원문 구절과 그래프 속 위치까지 따라가 보고, 문서 폴더를 수집하고, 평가를
실행해 비교하고, 내보낸 그래프를 탐색하고, 질의와 작업에 든 비용을 보고,
설정을 편집합니다. 한 사람이 한 호스트에서 쓰는 프로토타입이라 로그인이
없고, 따로 지정하지 않으면 `127.0.0.1`에만 바인딩합니다. 구조:
[설계 문서 §10.1](../design/surfaces.md#101-the-console-run-console-opt-in)(영문). 모든
플래그: [CLI 레퍼런스](../reference/cli.md#run-console)(영문).

## 콘솔 시작

콘솔은 `console` extra입니다. 웹 클라이언트는 Node.js 20.19 이상으로 한 번
빌드합니다(빌드 결과물은 저장소에 없습니다).

```bash
uv sync --inexact --extra console
(cd console/web && npm ci && npm run build)
uv run run-console --config-path config.yaml --source-directory ./workspace
```

`Console on http://127.0.0.1:8501/?token=…`이 출력되면 같은 호스트의
브라우저에서 그 주소를 엽니다. 토큰은 시작할 때마다 새로 만들어지고(실행기가
`UKR_CONSOLE_TOKEN`에 16자 이상을 지정하면 그 값), 페이지는 이를 HttpOnly
쿠키에 보관하며, 토큰이 없는 요청은 모두 거부합니다.

- `--source-directory`는 **작업 공간**입니다. 코퍼스로 고를 문서 폴더,
  `run-eval` 데이터셋(질문 목록을 담은 JSON 파일), 업로드가 들어가는
  `uploads/` 폴더가 여기에 있습니다. 기본값은 작업 디렉터리입니다.
- `--cache-directory`(기본값 `cache`)에는 수집 작업의 파이프라인 캐시와
  콘솔 자체 기록(`console/`: 질문 기록 `console.sqlite3`, 작업과 그 로그)이
  있습니다.
- `--config-path`는 설정 페이지가 편집하고 모든 작업이 쓰는 파일입니다.
  없으면 기본값으로 실행되고 아무것도 저장하지 않습니다. 불러올 수 없는
  파일이어도 콘솔은 시작하며, 모든 페이지에 오류를 보여 주고 설정
  페이지에서 고칠 수 있습니다.
- `--trace-url http://localhost:16686/trace/{trace_id}`는 각 답변을 그
  트레이스로 연결합니다(이 예는 Jaeger). `observability.backend: langfuse`와
  `LANGFUSE_HOST`를 설정했다면 이 플래그 없이도 Langfuse로 연결됩니다.
- 작업 공간의 `sample-questions.json`(문자열의 JSON 목록)은 질문 페이지의
  추천 질문이 됩니다.

빌드하지 않았다면 그 주소의 페이지가 클라이언트 빌드 방법을 알려 주고,
API는 `/api/status`에서 그대로 응답합니다. 클라이언트는 패키지가 실행되는
소스 체크아웃의 `console/web/dist`나 `UKR_CONSOLE_WEB_DIRECTORY`가 가리키는
곳에서 찾습니다. 설치한 휠에는 빌드가 없으므로 체크아웃에서 빌드한 뒤 이
변수로 그 `dist`를 가리키세요.

## 데모 실행

`console/demo/demo.py`는 작은 합성 코퍼스(라이다를 사는 로봇 제조사와
운송사, 창고, 검사 기관 이야기에 같은 거래의 한국어·일본어 메모를 더한
것으로, 모든 이름은 지어낸 것입니다), 이에 맞춘 답할 수 없는 질문 하나를
포함한 7문항 `run-eval` 데이터셋, 내장 SQLite 저장소와 증분 인덱싱을 켠
설정으로 작업 공간을 준비하고, `run-ingestion`으로 코퍼스를 수집한 뒤
`127.0.0.1:8501`에서 콘솔을 시작합니다.

코퍼스는 추가 패키지(extra) 없이 기본 설치로 파싱되는 형식을 섞어 두어,
출처 종류마다 인용이 어떻게 보이는지 확인할 수 있습니다.

| 파일 | 형식 |
|---|---|
| `supply-agreement.pdf` | PDF 3쪽: 당사자, 수치 표가 있는 납품·위약금 조항, 보증과 서명 |
| `quality-report.pdf` | PDF 2쪽: 검사 결과 표와 시정 조치 |
| `logistics-plan.md` | 제목과 목록이 있는 Markdown |
| `warranty-terms.html` | 표가 있는 HTML |
| `shipments.csv` | 운송 건마다 한 행인 CSV |
| `steering-minutes.json` | JSON 회의록 |
| `contract-summary.ko.md` | 한국어 Markdown 메모 |
| `quality-memo.ja.txt` | 일본어 텍스트 메모 |

PDF는 데모를 시작할 때 만듭니다(`console/demo/pdf_writer.py`, 표준
라이브러리만 쓰는 작은 생성기로 실행할 때마다 같은 바이트를 씁니다).
코퍼스를 대략 한 쪽 단위로 청크로 나누므로 PDF에서 인용한 구절은 그 쪽
번호를 함께 보여 줍니다(가짜 모델에서 *Who carries the lidar units to
Kestrel Depot, and how fast?*는 `supply-agreement.pdf` 2쪽을 인용합니다).

```bash
(cd console/web && npm ci && npm run build)
uv run --no-dev --extra console --extra local python console/demo/demo.py --models fake
```

가짜 모델과 Ollama는 로컬 모드로 실행되므로 `local` extra도 필요합니다(`bedrock`은
필요 없음). 데모는 무엇을 쓰거나 수집하기 전에 두 extra와 빌드된 웹 클라이언트를
확인하며, 데모에 SIGTERM을 보내면 데모가 띄운 콘솔도 멈춥니다.

| `--models` | 답하는 쪽 | 필요한 것 |
|---|---|---|
| `fake` | 루프백 포트의 결정적 모델 서버. 추출은 코퍼스의 이름을 찾고, 답변은 질문과 가장 가까운 컨텍스트 문장을 인용합니다. 스크린샷, 녹화, 테스트용이며 예시 가격으로 비용 열을 보여 줍니다 | 없음 |
| `ollama` | 로컬 프리셋 모델을 띄운 Ollama(다른 서버는 `--model-base-url`) | `ollama pull qwen2.5:7b-instruct`와 `bge-m3` |
| `bedrock` | `--region`(기본값 `AWS_REGION`, 없으면 `us-west-2`)의 Amazon Bedrock과 사용자의 자격 증명(SSO 세션, 인스턴스 역할). 저장소는 로컬에 둡니다 | 해당 리전의 모델 액세스. 모든 호출에 요금이 부과됩니다 |

스크립트는 접근 토큰이 붙은 콘솔 주소를 출력합니다. 작업 공간은
`.console-demo/`입니다(`--workspace`로 바꿉니다). 스크립트를
다시 실행하면 코퍼스는 다시 쓰지만, 설정은 처음 쓴 파일을 설정 페이지에서
저장한 내용(가격, 모델, 디렉터리)과 함께 그대로 두고 불러와지는지만 확인합니다.
가짜 모델은 유지한 설정에 적힌 포트에서 띄웁니다. `--reset-config`는 데모 설정을
다시 씁니다(`--models`를 바꿀 때도 이것을 씁니다). 수집은 새 문서가 없음을
확인하고 끝납니다. `--prepare-only`는 콘솔을 시작하기 전에 멈추고, `--no-ingest`는
수집을 건너뜁니다.

## 원격 호스트에서 접속

원격 호스트(클라우드 데스크톱, EC2 인스턴스)에서는 콘솔을 `127.0.0.1`에
둔 채 포트를 포워딩합니다.

- **SSH:** `ssh -L 8501:127.0.0.1:8501 <host>` 후 내 컴퓨터에서 출력된
  주소(`http://127.0.0.1:8501/?token=…`)를 엽니다.
- **VS Code Remote:** 콘솔이 시작되면 Ports 보기가 8501을 포워딩합니다
  (안 되면 직접 추가합니다). 포워딩된 주소를 엽니다.

데모를 `0.0.0.0`에 바인딩하지 마세요. 다른 주소는 `--allow-remote`가
필요하고, 그때는 앞단에 인증하는 리버스 프록시를 두어야 합니다. 포트에
닿는 누구나 인덱스를 질의하고, 작업을 시작하고, 설정을 편집할 수 있기
때문입니다.

## 페이지

**질문.** 질문 입력란과 전략 선택기가 있습니다. `auto`와 방법론별로 묶인
전략이 나오며, 인덱스 네임스페이스에 없는 전략은 이유와 함께 비활성화됩니다.
아직 아무것도 수집하지 않은 네임스페이스(빌드 기록이 없음)는 첫 질문 전에 그렇다고
알리며 수집 페이지로 가는 버튼을 보여 주고, 그 네임스페이스에 한 질문도 같은 내용을
알립니다.
답변은 답변 모델이 쓰는 대로 흘러나오고, 끝나면 최종 답변으로 바뀝니다
(거절이나 출력 가드레일이 결정한 답변이 최종입니다). 그 아래에는 `auto`가
고른 전략과 고른 방식(라우터가 지목함, 필터를 적용하는 유일한 후보였음,
라우터가 실패해 대체 전략을 씀)과 함께 전략, 시간, 입출력 토큰, 모델 호출
수, 비용(`evaluation.prices`에 가격이 있을 때), 재순위화 상태, 트레이스
링크가 한 줄로 나옵니다. 거절한 답변은 이유(컨텍스트 없음, 모델의
`[NO_ANSWER]`, 거절 정책에서 컨텍스트 부족)를, 차단된 답변은 가드레일이
막았음을 알려 줍니다. 답변의 인용 표식(`[1]`, `[2, 3]`)을 누르면 그 표식이
가리키는 출처가 출처 추적에서 열리고, 답변이 인용한 출처는 답변 아래에 파일과
쪽수와 함께 나옵니다. 컨텍스트에 없던 번호는 취소선으로 표시됩니다. 인용하지
않는 전략(기본값으로는 `global`과 `drift`, [인용](./query.ko.md#인용))의 답변은
표식 없이 쓰인 그대로 보여 줍니다. 체크를
풀지 않으면 후속 질문이 대화를 이어 갑니다. 페이지가 앞선 질문과 답변을 질문과
함께 보내므로(`RAGInput.history`) 설정을 저장하거나 수집을 마친 뒤에도 대화가
이어집니다.
검색 옵션에서 검색당 결과 수, 검색 유형, `key: value` 필터를 정합니다.

오른쪽 열은 콘솔의 대표 요소인 **출처 추적(provenance trace)**입니다.
답변 모델이 읽은 모든 출처가 순위대로 한 줄에 매달리고, 종류(구절,
엔티티, 관계, 커뮤니티 리포트)로 거를 수 있습니다. 출처를 열면 그 경로가
그려집니다. 엔티티나 관계는 같은 답변 안에서 자신을 말하는 구절(레일 위
정류장으로 이어지는 호)과, 답변이 읽지 않은 자기 구절 수를 보여 줍니다.
구절은 파일과 청크, 그리고 자신을 인용하는 그래프 출처를 보여 줍니다.
시드 그래프의 진술은 시드 그래프와 IRI를 보여 줍니다. **그래프에서
보기**는 그 엔티티(또는 엣지, 커뮤니티)에서 그래프 페이지를 열고, 그래프
위에 질문까지 거슬러 가는 경로를 이어 표시합니다.
출처마다 모델이 본 컨텍스트 표식이 붙고, 답변이 인용한 표식은 강조됩니다.
`structured` 전략의 그래프 쿼리 결과는 따로 한 출처로 나옵니다. 결과 표, 실행한
쿼리, 행 수와 표가 잘리지 않았는지, 그래프 저장소, 결과 엔티티가 인용한 구절을
보여 주고, **그래프에서 보기**는 결과의 첫 엔티티에서 그래프를 엽니다.

**수집.** 작업 공간의 문서 폴더가 파일 수, 크기, 형식과 함께 나오고,
폴더나 파일을 `uploads/`로 올릴 수 있습니다. 무엇을 만들지(방법론: 질의할
것만 만드세요. 나중에 추가하면 그 산출물만 만듭니다)를 고릅니다. 선택은
대상 네임스페이스의 빌드 기록에 있는 방법론에서 시작하므로, 다른 코퍼스를
같은 네임스페이스에 수집해도 그 전략이 쓰는 방법론이 모두 유지됩니다. 더
적게 빌드하는 선택(있는 방법론의 산출물을 이번 실행이 만들지 않는 경우)은
목록으로 보여 주고, 제거를 확인해야 시작합니다. 그러면 이 코퍼스뿐 아니라
네임스페이스의 모든 코퍼스에서 해당 전략이 더는 답하지 않습니다(API는
`confirm_narrowing` 없이는 `narrowing`으로 거부합니다). 추가
옵션에서 다른 인덱스 네임스페이스, 강제 재계산, 실행이 물을 수 있는 두
질문(다른 출처의 콘텐츠를 지우는 재설정, 대량 삭제)에 대한 답을 정합니다.
시작하면 코퍼스 폴더마다 정해진 파이프라인 ID(폴더 이름과 경로·네임스페이스의
해시)로 `run-ingestion`을 실행하므로, 같은 코퍼스를 다시 실행하면 이어서
하거나 증분으로 처리합니다. 실행이 질문 하나(이 코퍼스의 마지막 실행 이후
코퍼스나 설정이 바뀜, 재설정, 대량 삭제)에서 멈추면 어떤 질문인지 알려 주고,
그 질문에만 답해 다시 시작하도록 제안합니다(`--confirm-integrity`,
`--confirm-reset`, `--confirm-deletions`). 추가 옵션에서 미리 체크해 둘 수도
있습니다. 실행
단계는 끝나는 대로(파이프라인 자체 메타데이터에서 읽어) 정류장 열로
나타나며, 시간, 출력, 모델 호출, 실패한 단계의 오류와 실패한 파일, 로그의
끝부분을 보여 줍니다. 끝난 실행은 남긴 WARNING 수와 마지막 20개를 보여 주고, 문서를
처리했지만 엔티티를 하나도 추출하지 못한 실행을 따로 표시합니다. 중지는 CLI가 대비한 중지 신호를 보냅니다. 끝난
단계는 남고, 같은 코퍼스의 다음 실행이 이어서 진행합니다. 콘솔이 멈출 때
실행 중이던 작업은 콘솔을 다시 시작하면 유실됨으로 표시됩니다(네임스페이스는
비워지고, 저장소는 파이프라인의 네임스페이스 리스가 계속 지킵니다). 업로드는
최대 500개 파일 또는 100MiB씩 나눠 보내며, 서버는 요청 하나에 파일
10,000개와 500MiB까지 받습니다. 페이지는 수집이 읽지 않는 파일(다른 형식의
파일, 그리고 이름이 `.`으로 시작하는 숨김 파일이나 폴더와 `__pycache__`)을
빼고 보내며, 서버는 그런 파일이 든 요청과 한 경로를 파일이자 폴더로 쓰는
요청(`upload_conflict`)을 거부합니다. 요청 하나는 전부 쓰이거나 하나도 쓰이지
않으므로, 거부된 요청은 폴더를 그대로 두고 새로 만든 폴더도 남기지 않습니다.

**평가.** 데이터셋(질문 수, 답할 수 없는 질문 수, 어떤 평가기에 쓰이는지가
나옵니다), 전략(첫 번째가 기준선), 반복 횟수, 클로즈드북 비교군, 쌍대
심사, 회귀 게이트(`run-eval --fail-if`처럼 `MEASURE:STAT<OP>VALUE`), 실패
허용치를 고릅니다. 시작하면 `evaluation.outputs_directory` 아래 전용
디렉터리로 `run-eval --output-format json`을 실행하고, 진행률에는 답변
수(로그에 남는 답변 배치의 진행 줄에서 읽으며, 약 10%나 1분마다 갱신)와
저장된 실행 수가 나옵니다. 교차 실행(`evaluation.run_order`, 둘 이상일 때
기본값)은 한 배치로 답한 뒤 모든 답변이 나와야 채점하고 저장하므로, 중지하면
실행이 하나도 남지 않습니다. 하나씩 실행할 때는 중지해도 끝난 실행이
남습니다. 저장된 실행(콘솔이든 다른 `run-eval`이든)을 열면 결과 표(전략별
각 지표의 평균), 기준선 대비 쌍대 비교(지표마다 한 행: 행마다 고유한
눈금에 그린 평균 차이와 구간, 승·무·패)가 나옵니다. 지표 이름에 마우스를
올리면 그 설명과 높을수록 좋은지 낮을수록 좋은지가 나옵니다. 다중 비교를 보정한
비교([전략 비교](./evaluate.ko.md#전략-비교))에서는 Holm 보정 p값이 비교의 유의수준보다
작을 때만 더 좋음 또는 나쁨으로 표시하고, 그 p값과 묶음별 동시 신뢰 구간(신뢰
수준 포함)을 보여 주며, 주 지표를 표시합니다. 이전 비교와, 질문별 쌍이 없는
차이나 클로즈드북 비교군은 구간이 0을 포함하지 않는지로 판단합니다. 이어서
비교의 경고, 질문당 비용(USD, 토큰, 중앙값과 95번째
백분위 시간), 거절(비율, 그리고 답할 수 없는 질문에 대한 정밀도와 재현율),
쌍대 심사를 켰다면 답변 길이 구간별 승률이 나옵니다. **질문별** 표는 열 때
읽어 오며, 질문마다 전략별 주 지표 점수(반복 실행의 평균)와, 보이는 비교
대상이 기준선에 비해 이겼는지·비겼는지·졌는지를 보여 주고 결과로 거를 수
있습니다. 질문을 열면 정답과 전략별 답변을 나란히 볼 수 있습니다. 답할 수 없는 질문으로
표시된 질문은 답변마다 거절했는지를 보여 줍니다(거절이 맞는 답입니다). 작업의
게이트는 통과 또는 실패로 표시됩니다.

**그래프.** 네임스페이스의 `visualization_data.json`(기본값은 가장 최근
파일)을 그립니다. 전체 빌드는 네임스페이스의 전체 그래프를 쓰고, 콘솔 작업은
그래프를 내보내지 않습니다. 그래서 페이지를 열었을 때 저장소의 현재 상태를 보여 주는
파일이 없으면(증분 작업 뒤) 콘솔이 `run-visualization`처럼 저장소에서 만듭니다.
연결 요소마다 시드를 고정한 배치로 그립니다. 드래그나 화살표 키로
이동하고, 휠이나 `+`/`-`로 확대합니다. 커뮤니티나 유형으로 색을 칠하며(큰
여덟 묶음, 나머지는 회색, 범례에 이름 표시), 이름으로 엔티티를 찾습니다.
엔티티를 고르면 유형, 설명, 연결, 구절, 커뮤니티, IRI, 스키마 상태를
보여 주고, 이어 갈 관계를 나열합니다. 커뮤니티 탭은 계층을 나열하고
커뮤니티 구성원을 강조합니다. 분석 탭은 엔티티, 관계, 연결 요소 수와
밀도를 세고, 연결 수 히스토그램을 그리고, 엔티티와 관계 유형, 스키마 적합성
(스키마 안, 밖, 미확인), 근거(문서, 시드 그래프, 둘 다)를 셉니다. 그래프
아래에 모든 엔티티 표가 있습니다.

**대시보드.** 최근 하루, 한 주, 한 달, 일 년 동안 콘솔로 한 질문과 그
중앙값·95번째 백분위 시간, 거절과 오류 수, 비용, 일별 질문 수와 중앙값
시간, 전략·모델·역할별 호출, 토큰, 비용, 그리고 작업의 소요 시간, 호출,
토큰, 비용을 보여 줍니다. 비용에는 `evaluation.prices`가 필요합니다
([비용과 가격](./evaluate.ko.md#전략-비교)). 가격이 없는 모델은
무료로 세지 않고 목록에 표시한 뒤 비용에서 뺍니다. 질문 기록 지우기는
기록된 질문을 삭제합니다.

**설정.** 설정 파일을 필드나 YAML로 편집합니다. 필드는 설정 스키마에서
오며, 키마다 설명(도움말), 기본값, 파일에 설정됐는지가 나옵니다. 키나
설명으로 찾을 수 있습니다. 변경 사항은 오른쪽에 모이고, 검토는 실행이
파일을 불러오듯(알 수 없는 키와 `UKR__` 환경 변수 포함) 확인한 뒤 파일의
diff, 오류, 경고를 보여 줍니다. 저장하면 파일을 쓰며, 그사이 디스크의
파일이 바뀌었다면 거부합니다. 필드에서 저장하면 YAML의 주석이 사라지고
(검토 화면이 알려 줍니다), YAML 탭에서 저장하면 주석이 남습니다. 공급자가
요청을 보내는 곳(`providers.*.base_url`, `aws.neptune.endpoint`,
`aws.opensearch.endpoint`, 그 포트)을 바꾸는 변경은 검토 화면에 표시되고,
거기서 확인해야 저장됩니다. 그 요청에는 콘솔 환경에 있는 해당 공급자의 자격
증명(API 키, 저장소 비밀번호, 서명된 AWS 요청)이 함께 가기 때문입니다.
파일이나 디렉터리 경로(이름이 `path`, `directory`이거나 `_path`, `_directory`로
끝나는 모든 키: 콘솔이 다루는 `evaluation.outputs_directory`와
`graph.visualization.outputs_directory`, 그리고 SQLite 저장소 파일,
`logging.log_file_path`, 스키마·시드 그래프 파일, 파싱 디렉터리처럼 콘솔의
작업이 읽고 쓰는 경로)를 바꾸는 변경도 같은 방식으로 확인합니다. 새 경로를
페이지에 여는 것이기 때문입니다. 파일은 통째로 씁니다(옆에 임시 파일을 만들어 이름을 바꿔 덮어씀). 방법론
탭은 `indexing.methodologies`를, 트레이싱 탭은 `observability`를 편집하고
`LANGFUSE_*`, `PHOENIX_*`, `OTEL_*` 변수가 설정됐는지만(값은 절대 아님)
보여 줍니다. 유효 설정 탭은 실행이 받는 설정을 보여 줍니다. 다음 질문과
작업부터 저장된 파일을 씁니다.

## 읽고 쓰는 곳

- **읽기:** 작업 공간, 캐시 디렉터리, 평가 출력,
  `graph.visualization.outputs_directory`. 페이지가 가리키는 모든 경로는
  (심볼릭 링크까지) 해석한 뒤 이 중 한 곳 안에 있어야 합니다. 폴더 목록은 심볼릭
  링크를 건너뛰고, 수집 작업은 `run-ingestion`과 마찬가지로 해석한 경로가 폴더 밖인
  코퍼스 파일을 건너뜁니다(WARNING으로 알림).
- **쓰기:** 작업 공간의 `uploads/`, 캐시 디렉터리(파이프라인 캐시,
  `console/`), 평가 출력, 설정 파일. 저장소는 설정에 따라 `run-ingestion`
  작업이 씁니다.
- **비밀 값:** 페이지로 보내지도, 파일에 쓰지도 않습니다. 비밀 값
  (`providers.llm.api_key`, `aws.opensearch.password`)을 담은 파일은 값을
  가린 필드로 볼 수는 있지만 콘솔에서 저장할 수는 없습니다. 먼저 해당 환경
  변수(`UKR__PROVIDERS__LLM__API_KEY`)로 옮기세요.
- **질문:** 대시보드 저장소는 질문마다 텍스트, 전략, 시간, 사용량, 비용을
  남기고, 답변이나 출처는 남기지 않습니다.

## 보안

- 기본값은 루프백이고, 다른 주소는 `--allow-remote`와 인증 프록시가
  필요합니다. 콘솔에는 계정이 없으며, 실행할 때마다 만드는 접근 토큰(출력된
  주소에 담겼다가 HttpOnly, SameSite=Strict 쿠키가 됨)이 모든 요청에
  필요합니다.
- 무언가를 바꾸는 요청에는 다른 사이트의 폼이 보낼 수 없는 헤더가 있어야
  하고, 다른 출처의 요청은 거부합니다. 루프백에서는 다른 호스트 이름으로 온
  요청을 거부합니다(DNS 리바인딩). 어떤 응답에도 CORS 헤더가 없습니다.
- 페이지는 다른 호스트에서 아무것도 불러오지 않습니다. 글꼴(Pretendard,
  Pretendard JP, JetBrains Mono, SIL Open Font License, 전문은
  `console/web/public/licenses/`)은 빌드에 포함되므로 오프라인과 프라이빗
  VPC에서도 동작합니다.
- 인덱스 네임스페이스마다 수집이나 평가 작업은 동시에 들어온 요청까지
  포함해 한 번에 하나입니다. 다른 곳에서 시작한 `run-ingestion`은
  파이프라인의 네임스페이스 리스가 계속 막아 줍니다. 콘솔을 멈추면 그
  작업들을 멈추고 CLI의 중지 유예 시간(110초)까지 기다립니다.

## 라이트와 다크

페이지에는 라이트 테마와 다크 테마가 있습니다. 기본값은 운영체제 설정을
따르며, 상단 바(좁은 화면에서는 **메뉴** 안)의 **테마**에서 *시스템*, *라이트*,
*다크*로 바꿀 수 있고 선택은 브라우저에 저장됩니다. 그래프, 차트, 근거
강조 표시도 테마를 따릅니다.

## 언어

페이지는 영어, 한국어, 일본어, 중국어 간체, 독일어, 스페인어, 프랑스어,
이탈리아어, 포르투갈어, 러시아어(라이브러리가 지원하는 언어)로 볼 수
있습니다. 상단 바에서 고르며, 기본값은 브라우저 언어이고
선택은 브라우저에 저장됩니다. 문서, 질문, 답변은 어떤 언어든 됩니다.
숫자, 날짜, 기간, 통화는 고른 언어의 형식을 따릅니다.

언어를 추가하려면 `console/web/src/i18n/locales/en.json`을 `<code>.json`으로
복사해 값을 번역하고(모든 키와 `{{placeholder}}`를 유지합니다. 복수형 키는
그 언어에 `Intl.PluralRules`가 주는 접미사 `_one`, `_few`, `_many`,
`_other` 등을 씁니다), `src/i18n/glossary/<code>.json`에 용어집을 더하고,
`src/i18n/i18n.tsx`의 `LOCALES`에 등록합니다. 로케일에 키가 빠지거나
남거나, 자리 표시자가 바뀌거나, 복수형이 틀리면 `npm test`가 실패합니다.

## 웹 클라이언트 개발

```bash
cd console/web
npm ci
npm run dev        # http://127.0.0.1:5173, /api는 8501의 run-console로 전달
npm run typecheck && npm run lint && npm test
npm run build
```

- 디자인 개요(팔레트, 글자 크기 체계, 참고 사례, 피할 것)는
  [`console/web/DESIGN.md`](../../console/web/DESIGN.md)(영문)에 있습니다.
  방향을 바꿀 때는 이 문서부터 고칩니다. `npm run fonts`(`dev`, `build`,
  `typecheck`가 먼저 실행)는 `@fontsource` 패키지에서
  `src/styles/fonts.css`를 만듭니다. 스타일이 쓰는 굵기와 문자 범위만, WOFF2로만
  담습니다.
- `npm run test:smoke`는 실행 중인 콘솔(`CONSOLE_URL`, 토큰이 붙은 출력
  주소)에 대해 Playwright 스모크 테스트를 실행합니다.
  브라우저가 없으면 건너뜁니다(`npx playwright install chromium`).
- `node scripts/screenshots.mjs --base-url <url> --out <dir>`은 모든 페이지의
  스크린샷을 찍습니다(`--locales en,ko --widths 1440,390`).
- `node scripts/record-tour.mjs --base-url <출력된 주소> --out <dir>`은 25초
  이내의 정해진 둘러보기(질문, 인용한 파일과 쪽, 출처, 그래프로 이어지는 경로, 평가 비교,
  대시보드)를 녹화합니다. 단계마다 보여 줄 상태를 기다리고, 깨진 상태를
  녹화하는 대신 스크린샷과 함께 실패하며, 모델 대기 시간은 잘라 냅니다.
  경로에 `ffmpeg`가 있으면 같은 구도의 MP4와 GIF로 씁니다.

## 한계

- 한 호스트의 한 사용자용입니다. 계정, 사용자 간 접근 제어, 브라우저 간
  공유 기록이 없습니다.
- 그래프 페이지는 큰 그래프에서 연결이 많은 엔티티 600개만 그립니다.
  나머지는 이름으로 찾거나 표에서 봅니다.
- 작업 진행률은 단계(수집) 단위, 또는 답변과 저장된 실행(평가) 단위이며,
  문서 단위가 아닙니다. 답변 수는 INFO 줄을 남기는 로그 수준
  (`logging.level`)에서만 셉니다.
- AWS 스택의 Neptune과 OpenSearch에 대해 콘솔을 실행하는 것은 CLI처럼
  설정으로 동작하지만, 아직 그 환경에서 측정하지 않았습니다.
